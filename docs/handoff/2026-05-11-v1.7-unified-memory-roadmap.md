## The architectural through-line

Every slice writes into the same notes substrate that slice 0
established. The canvas (MyceliumCanvas) shows them as nodes without
needing a separate view per kind:

```
 ┌─────────────────────────────────────────────────────────────────┐
 │  Notes substrate (kind enum + bySource scoping + backlinks)     │
 │     code   ←  A1 code-graph scanner                             │
 │     design ←  A2 markdown ingester (DESIGN.md per package)      │
 │     eval   ←  A3 eval runner persisting per (prompt, fixture)   │
 │     dom    ←  C1 HTTP browser snapshotter                       │
 │     visual_diff ← C2 structural comparator                      │
 │     trade  ←  B1 RSI / B2 Kronos signal generators              │
 └─────────────────────────────────────────────────────────────────┘
```

Each ingester follows the same hygiene pattern:
- Stable, deterministic note id with sortable suffix (timestamp / pair).
- `sourceType` + `sourceId` for scoped reconciliation via
  `NoteStore.bySource(sourceType, sourceId)`.
- Stale-edge removal passes `recordFeedback: false` so internal churn
  never poisons the learned mention policy.
- Machine-readable trailing block in the note body (```snapshot-meta /
  ```diff-meta / ```signal-meta) that round-trips back into a typed
  object without a separate index.

## What the planner now sees

`runPlanningStage` accumulates three optional prompt-context channels,
each backwards-compatible (omit ⇒ legacy behavior):

1. **IMPACT RADIUS** (A1) — files that import the targeted file.
2. **DESIGN SYSTEM** (A2) — relevant DESIGN.md sections.
3. **PRIOR ATTEMPT FEEDBACK** (pre-A) — existing reviseContext.

`runBuildingStage` accumulates one optional gate:
4. **runEvals** (A3) — pure read of the latest planner-eval verdicts;
   soft_fails the cycle with `failureKind='eval'` on regression.

The dom gate (C1) and visual diff (C2) ship the substrate but are
intentionally NOT wired into building.ts — the dev server isn't
guaranteed up during cycles. Wiring them is a one-line opt-in.
